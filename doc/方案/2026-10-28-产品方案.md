# MuseLab 音乐工坊 · 产品方案

> 版本：v0.1（2026-10-28）｜提出：CEO｜落地：z-biz-tool-music
> 一句话：**一句话描述 → 一首完整的曲子 → 五线谱 / 简谱 / 钢琴卷帘同步出来 → 能播、能改、能导出。**

---

## 0. 这份方案要回答什么

CEO 的原话拆成六条硬要求：

1. 智能化从头到尾做出一首音乐（不是拼贴片段，是完整曲子）
2. 谱子能造出来（不是只能听，要有真正的乐谱）
3. 像 Mac 上那类音乐软件（Logic / GarageBand / MuseScore 的操作手感）
4. 多音色混音也能做
5. 简谱、钢琴谱各种谱都能出
6. 能接入 AI，AI 真的帮人写曲子

本方案在第 5 节给出能力矩阵，第 6 节给出架构，第 7 节给出数据模型，第 8 节是 AI 链路，第 12 节是路线图。**本轮交付 v0.1 可运行仓**，不是 PPT。

## 1. 为什么这个产品值得做（家族视角）

家族现有 17 个仓的体检结论：工程 4.3 分、商业化 1.9 分。工程不差，缺的是**愿意付钱的理由**。

现有产品都在"效率/工具"象限（文件、数据库、笔记、终端、看板），用户画像偏开发者与办公人群，付费意愿被免费替代品压得很低。音乐创作是家族里**第一件"创作型"产品**：

| 维度 | 办公工具 | 音乐创作 |
|---|---|---|
| 用户动机 | 不得不做 | 想做、想发出去 |
| 替代品价格 | 大多免费 | Logic Pro ¥1,298 / Sibelius 订阅 ¥700+/年 / Flat.io ¥60/月 |
| 成功感 | 干完就关 | 有作品，会分享、会回来改 |
| AI 价值 | 提速 20% | 从"不会写"到"有一首"——跨越门槛 |

结论：这是家族**唯一有"作品感"**的产品，也是最容易做出 demo 视频、最容易在小红书/B 站自传播的品类。

## 2. 用户与场景

| 人群 | 现在的做法 | 痛点 | 我们的价值 |
|---|---|---|---|
| **音乐老师 / 琴童家长**（主力付费） | 手写简谱拍照、Word 排版 | 简谱排版软件又老又贵（作曲大师、雅乐），五线谱软件不会打简谱 | 简谱原生支持 + AI 起稿，10 分钟出一份能打印的谱 |
| **业余创作者 / 短视频配乐** | 手机哼唱、找免版权曲库 | 不会记谱、不会配器，成品要花钱买 | 一句话出和弦进行 + 旋律 + 伴奏，直接导 WAV |
| **合唱团 / 乐队排练** | 到处找谱、手动移调 | 移调、分声部、打印 | 一键移调/分声部/导出 PDF 与 MIDI |
| **学生 / 艺考生** | MuseScore + 手抄简谱 | 乐理看不懂，和声不会配 | AI 讲和声 + 试听对比 |

**核心买单人**：音乐老师与琴童家长（对"能打印的谱"有刚需、对价格不敏感、会复购教材包）。

## 3. 竞品与开源调研

### 3.1 商业竞品

| 产品 | 平台 | 强项 | 短板（我们的机会） |
|---|---|---|---|
| **MuseScore 4** | 全平台 | 免费、生态大、MusicXML 事实标准 | 简谱只有插件且残废；无 AI 作曲；上手陡 |
| **Sibelius / Dorico** | Win/Mac | 专业排版 | ¥5,000+，个人用户买不起 |
| **Logic Pro** | Mac | 音源与混音顶级 | ¥1,298、只有 mac、不记谱（谱面弱） |
| **GarageBand** | Mac/iOS | 免费、好用 | 无乐谱、无简谱、AI 只有鼓手 |
| **Flat.io / Noteflight** | Web | 协作、易用 | 订阅制、离线差、无简谱、AI 弱 |
| **作曲大师 / 雅乐简谱** | Win | 简谱专业 | 界面二十年没变、只 Win、无 AI |
| **Suno / Udio** | Web | 一句话出歌 | **出的是音频，不可编辑、无谱、不可改一个音** |

**关键空白**：*"AI 出成品"* 与 *"谱面可编辑"* 之间没有桥。Suno 给你一首没法改的歌，MuseScore 给你一张要自己写的纸。**MuseLab 的位置就是这座桥**：AI 出的是一份**结构化乐谱**，所以既能听、又能改、还能打印。

### 3.2 开源库调研（选型依据）

| 库 | 许可 | 能力 | 我们怎么用 |
|---|---|---|---|
| **abcjs** 6.7.2 | MIT | ABC 记谱法渲染 SVG + 自带 synth | **五线谱排版引擎**（本仓已用） |
| **VexFlow** 5.0 | MIT | 低层记谱原语 | 备选；需自己实现换行/连桁/调号，成本高 |
| **OpenSheetMusicDisplay** 2.2 | AGPL-3.0 ⚠️ | MusicXML → SVG，质量高 | **不用**：AGPL 与商业闭源冲突 |
| **alphaTab** 1.8 | MPL-2.0 | 吉他谱/TAB/MusicXML | v0.2 做吉他谱时接 |
| **Verovio** 6.3 (WASM) | LGPL-3.0 ⚠️ | MEI 排版质量最好 | 谨慎：LGPL 动态链接可接受，但体积 8MB+ |
| **LilyPond** | GPL-3.0 ⚠️ | 排版质量天花板 | **只能作为外部命令调用**，不静态链接、不随包分发 |
| **MuseScore** | **GPL-3.0** ⚠️ | 完整 DAW+记谱 | **禁止嵌入**；只做 MusicXML 互操作（文件格式不受 GPL 传染） |
| **Tone.js** 15.1 | MIT | Web Audio 封装、离线渲染 | **播放引擎**（本仓已用） |
| **@tonejs/midi** 2.0 | MIT | MIDI 读写 | MIDI 导入导出 |
| **smplr** 1.1 / soundfont-player | MIT | SoundFont 采样播放 | v0.2 接真采样音源 |
| **rustysynth** | MIT | Rust 纯实现 SF2 合成器 | v0.3：本地 SF2 → 离线渲染成 WAV（比 Web Audio 音质好、可后台批量） |
| **music21 / abjad** | BSD | Python 乐理分析/生成 | 不引入（Python 运行时太重），只借鉴算法 |
| **简谱生态** | — | **几乎空白**（npm 无可用包） | **自研**：这是护城河，也是本仓 `src/core/jianpu.ts` 从零实现的原因 |

> 一句话选型结论：**abcjs 管五线谱（MIT，能商用）、Tone.js 管声音（MIT）、简谱与钢琴卷帘自研（无处可抄）、AGPL/GPL 的 OSMD 与 MuseScore 一律不碰**。

## 4. 差异化定位

```
        Suno/Udio                MuseLab                 MuseScore/Sibelius
   一句话 → 音频（不可改）   一句话 → 乐谱（可改可听可印）      手工 → 乐谱（好听不了）
                                  ▲
                          我们站在这条缝里
```

三条护城河，按可复制难度排序：

1. **简谱原生排版**（难抄：没有开源实现，中文乐谱市场刚需，海外产品不做）
2. **ABC 作为 AI 中间语言**（易做但很少人做对：LLM 对 ABC 的掌握远好于对 MusicXML 的掌握，token 省 10 倍，出错可校验）
3. **同一份 IR 喂四个视图**（五线谱/简谱/卷帘/混音台），改一个音四处同步

## 6. 技术架构

### 6.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ UI 层（React 19 + antd 6）                                │
│  五线谱 StaffView │ 简谱 JianpuView │ 卷帘 PianoRoll │ 混音 Mixer │
│  AI 面板 │ 作曲面板 │ 属性检查器 │ 走带条 Transport         │
├──────────────────────────────────────────────────────────┤
│ 状态层 src/state.ts（zustand）                            │
│  score（唯一真源）· 选区 · 视图 · 播放态 · 设置（落盘）      │
├──────────────────────────────────────────────────────────┤
│ 内核层 src/core/（纯函数、零 DOM、可 node 直测）             │
│  model 乐谱IR · theory 乐理 · abc 解析/生成 · midi          │
│  musicxml · jianpu 排版模型 · compose 规则作曲 · ai 提示词   │
├──────────────────────────────────────────────────────────┤
│ 引擎层 src/audio/engine.ts（Tone.js）                      │
│  12 音色族 · 混音总线 · 走带 · OfflineAudioContext 导 WAV   │
├──────────────────────────────────────────────────────────┤
│ 平台层 src-tauri（Rust）                                   │
│  单实例 · 原生保存/打开对话框 · updater · 文件读写命令       │
└──────────────────────────────────────────────────────────┘
```

**为什么内核层必须零 DOM**：`scripts/verify.ts` 与 `tests/*.test.ts` 要在 Node 里直跑（家族规范：收口 = typecheck + 单测 + build 全绿）。乐谱内核一旦沾 DOM 就无法回归测试，而乐谱内核正是 bug 密度最高的地方。

### 6.2 关键技术决策

| 决策 | 选择 | 理由（含被否方案） |
|---|---|---|
| 五线谱渲染 | **abcjs**（IR→ABC→SVG） | 自己实现连桁/调号/符杠要 3k 行且做不过它；VexFlow 太底层 |
| AI 输出格式 | **ABC 文本** | LLM 对 ABC 的准确率远高于 MusicXML（XML 冗长、易坏结构）；ABC 一份 32 小节曲子约 400 token，MusicXML 要 6000+；有语法错误能定位到小节 |
| 内部 IR | **绝对时间扁平音符表** | 曾考虑"每小节一组音符"，编辑/移调/量化每次都要跨小节搬运；扁平表让所有变换变成一次 map |
| 简谱 | **自研** | 无可用开源实现；排版规则可枚举（数字+点+线+附点） |
| 钢琴卷帘 | **Canvas 2D 手绘** | 500+ 音符用 DOM 会掉帧；Canvas 便于做 60fps 播放头 |
| 音频 | **Tone.js 实时 + Offline 导出** | 无需随包分发采样（省 200MB 与授权风险）；v0.3 接 rustysynth+SF2 提升音质 |
| 原生文件 | **Rust 自定义命令**（dialog + std::fs） | 不引 tauri-plugin-fs 的 scope 配置复杂度；落盘路径由用户对话框决定，天然安全 |
| 工程格式 | **`.zmusic` = JSON** | 人类可读、可 diff、可被 AI 直接改；二进制格式对 v0.x 是负担 |

### 6.3 端口与家族约定

- 前端 dev 端口 **5200**（5173 被 8 个仓占用，1420 被 db/sys，5199 被 math）
- 技术栈与 math 对齐：Tauri 2 + React 19 + antd 6 + zustand 5 + Vite 6 + TS strict
- 图标：`assets/app-icon.svg` 为唯一手写源，母题「五线谱 + 八分音符」，配色 `#1B2B6B → #FF6B6B`（家族剪影表内无重复）
- 遵守 `008_组织规范/004_产品交互契约.md`：三态、二次确认、不假成功、aria-label、900×600 可用

## 7. 数据模型（IR）

```jsonc
{
  "v": 1,
  "title": "秋日私语",
  "composer": "MuseLab AI",
  "key": { "tonic": 0, "mode": "major" },   // C 大调；tonic 为 0-11 半音
  "time": [4, 4],
  "tempo": 88,
  "tracks": [
    {
      "id": "t1", "name": "主旋律", "instrument": "piano", "program": 0,
      "volume": 0.8, "pan": 0, "mute": false, "solo": false,
      "clef": "treble", "color": "#FF6B6B",
      "notes": [
        // start / dur 单位都是「拍」（四分音符=1），绝对时间
        { "id": "n1", "start": 0, "dur": 1, "pitch": 72, "vel": 88, "tie": false },
        { "id": "n2", "start": 1, "dur": 0.5, "pitch": 74, "vel": 80 }
      ]
    }
  ]
}
```

约定：

- `pitch` 用 MIDI 号，`-1` 表示休止（休止参与节拍占位，便于排版与导入）
- 小节边界由 `time` 推导（`beatsPerMeasure = time[0] * 4 / time[1]`），v0.1 不支持变拍号（v0.2 支持，模型已预留 `timeChanges` 字段位）
- 所有编辑操作返回**新 score**（不可变），便于撤销栈与差分对比

## 8. AI 作曲链路

### 8.1 为什么用 ABC 当中间语言

```
用户一句话
   ↓  提示词（含曲式/调性/长度/难度约束 + ABC 语法约束 + 一个 few-shot 例子）
LLM（OpenAI 兼容接口，任意 baseURL）
   ↓  ABC 文本（约 400-1500 token）
严格子集解析器 src/core/abc.ts（不认识的写法直接报「第 X 小节第 Y 个记号」）
   ↓
Score IR ──→ 五线谱 / 简谱 / 卷帘 / 播放 / MIDI / MusicXML
```

关键设计：

- **只认子集**：`X T M L Q K V` 头 + 音符 + 时值 + 休止 + 和弦 + 连音线 + 小节线。解析器**拒绝**而不是静默忽略——静默忽略会让 AI 的错变成用户看到的错。
- **失败可回退**：解析失败时把错误回抛给模型重试一次（带错误信息），仍失败则降级到本地算法作曲，界面明确标注「本次为本地算法生成，未使用 AI」。
- **无 Key 也能用**：`compose.ts` 是一套规则作曲器（和弦进行 + 旋律动机发展 + 低音 + 伴奏织体），确定性随机（seed），所以产品在没配置任何 Key 的机器上依然能"从头到尾造出一首曲子"。

### 8.2 四种玩法

| 玩法 | 输入 | 输出 |
|---|---|---|
| 整曲生成 | 「写一首 16 小节的 C 大调钢琴小品，温柔，60-80 BPM」 | 完整多轨乐谱 |
| 续写 | 当前最后 4 小节 + 「往明亮的方向发展」 | 追加 8 小节 |
| 变奏 | 选中主题 + 「改成小调、加切分」 | 主题变奏 |
| 润色 | 当前谱 + 「低音太单调，加走动低音」 | 改后的同结构乐谱 |

### 8.3 隐私与成本

- API Key 只存本机 `localStorage`，不入仓、不上传（`.gitignore` + 代码内不打印）
- 请求体只含乐谱 ABC 与文字要求，不含用户身份
- 一次整曲生成 ≈ 2k token 输入 / 1.5k 输出 ≈ ¥0.03（按 GPT-4o-mini 级价格）；商业化时可包月含额度

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：工程名 │ 新建/打开/保存 │ 导出▾ │ 视图切换 │ 主题 │ 设置  │
├──────────┬───────────────────────────────────────┬───────────┤
│ 轨道列表  │            主视图区                    │  右侧面板  │
│ + 新建轨  │  五线谱 / 简谱 / 卷帘 / 混音台          │ AI 作曲   │
│ 音量声像  │  （播放头随播放滚动，音符高亮）           │ 乐理工具  │
│ 静音独奏  │                                       │ 属性检查  │
├──────────┴───────────────────────────────────────┴───────────┤
│ 走带条：⏮ ⏵ ⏸ ⏹ │ 位置 3.2.1 │ BPM 88 │ 拍号 4/4 │ 循环 │ 节拍器 │
└──────────────────────────────────────────────────────────────┘
```

交互硬要求（对照契约）：

- 播放在无音符时按钮置灰并说明「当前工程没有音符」
- 新建/打开/关闭未保存工程 → 二次确认，文案含工程名
- 导出三态：进行中 loading、成功提示含文件名、失败给出原因与重试
- AI 生成可取消（AbortController），取消后不写回乐谱
- 所有纯图标按钮带 `aria-label`

## 13. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| abcjs 排版对复杂节奏（跨小节连音、多声部）表现有限 | 中 | IR 层面把跨小节音符切分；多声部 v0.2 用多 voice |
| LLM 生成的 ABC 语法错误率高 | 高 | 严格子集解析 + 自动重试一次 + 本地算法兜底（已实现） |
| 简谱排版规则众口难调（不同教材习惯不同） | 中 | 排版参数可调（每行小节数、字号、是否显示调号唱名） |
| Web Audio 音色不如采样 | 中 | 明示"内置合成音色"；v0.3 接 SF2 |
| 与 MuseScore 的 MusicXML 互操作细节 | 中 | 只导出标准 4.0 partwise，用 MuseScore 实机验证 |

## 14. 验收标准（v0.1）

1. `npm run typecheck` / `npm test` / `npm run verify` / `npm run build` 全绿
2. 打开即有示例曲，五个视图都能出来（五线谱/简谱/卷帘/混音台/AI 面板）
3. 播放能出声、播放头走、循环与节拍器可用
4. 导出 MIDI 能被 MuseScore/Logic 打开；导出 MusicXML 能被 MuseScore 打开；导出 WAV 能播
5. AI 面板：无 Key 时给出明确提示并回退本地算法；有 Key 时生成结果可解析
6. 简谱与五线谱显示同一份 IR 的同一串音（同一小节音符数与音高级别一致）
